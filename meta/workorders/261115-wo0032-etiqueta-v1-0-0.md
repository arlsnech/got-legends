## Depois de aplicar — conferencia antes do commit

Cada passo traz **quem roda**, **como chega la** e **qual pergunta ele NAO responde**.

1. **O build passa.** Quem roda: quem aplica. Como: `npm run build` → sai sem erro e gera `dist/`.
   **Nao responde:** se o app funciona na tela — para isso, `npm run preview` e abrir (opcional; o codigo nao mudou desde a `wo0027`).
2. **Uma versao nova, um Nao lancado vazio.** Quem roda: quem aplica. Como: `grep -c "^## \[1.0.0\] — 2026-11-15" meta/CHANGELOG.md` → **1**; `grep -c "^## \[Não lançado\]" meta/CHANGELOG.md` → **1**; `grep -c "guia original perdido" meta/CHANGELOG.md` → **1** (so a linha nova de «Removido do registro»).
   **Nao responde:** se a 1.0.0 lista tudo o que entrou — o bloco nao foi revisto item a item.
3. **STATUS coerente.** Quem roda: quem aplica. Como: `grep -c "1.0.0-beta" meta/STATUS.md` → **0**; `grep -c "Etiquetar a versão" meta/STATUS.md` → **0**.
   **Nao responde:** nada alem disso.

## Commit, tag e push — mensagem SEM acento

A propria WO entra no `git add`. Depois do commit, a tag anotada **nesse commit**, e os dois pushes.

```
git add meta/CHANGELOG.md meta/STATUS.md meta/workorders/261115-wo0032-etiqueta-v1-0-0.md
git commit -m "chore(release): etiqueta a versao 1.0.0"
git tag -a v1.0.0 -m "v1.0.0 - primeira versao estavel: planejador, exportacao em texto e em imagem (F1-F3)"
git push
git push origin v1.0.0
```
